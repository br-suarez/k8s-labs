========== What is actually inside each image ==========

Naive ships gcc, python3, 69 node_modules entries including the esbuild
devDependency, and runs as root.

Note what does NOT change: npm is present in BOTH. It ships with every
node:* base image including -alpine, so multi-stage does not remove it.
Getting rid of the package manager entirely needs a distroless or scratch
base image, which is a separate decision from multi-stage.

$ sh -c docker run --rm --entrypoint sh checkout-api:naive -c 'which npm node python3 gcc 2>/dev/null; echo "node_modules entries: $(ls /app/node_modules 2>/dev/null | wc -l)"; echo "esbuild present: $(test -d /app/node_modules/esbuild && echo yes || echo no)"; echo "runs as uid: $(id -u)"'

========== Layer cache behaviour on a source-only change ==========

Changing one line of src/server.js and rebuilding both.

The first attempt at this used 'touch', which proved nothing: Docker's COPY
cache keys on file CONTENT, not mtime, so both builds were fully CACHED. The
file has to actually change.

--- naive rebuild (COPY . . before npm install) ---
#6 CACHED
#7 [3/5] COPY . .
#8 [4/5] RUN npm install
#9 [5/5] RUN npm run build
elapsed: 6s

--- multi-stage rebuild (COPY package*.json first) ---
#8 [build 3/6] COPY package*.json ./
#8 CACHED
#9 CACHED
#10 [build 4/6] RUN npm ci
#10 CACHED
#11 [build 5/6] COPY src ./src
#12 [build 6/6] RUN npm run build
#13 CACHED
#14 [runtime 3/4] COPY --from=build /app/dist ./dist
#14 CACHED
elapsed: 2s

(src/server.js restored)
